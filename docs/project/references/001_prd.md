# Product Requirements Document (PRD)

## 1. Executive Summary

**Problem Statement**: Building an admin dashboard from scratch requires weeks of repetitive setup — authentication, user management, role-based access, file uploads, and SPA architecture — before a team can write a single line of business logic.

**Proposed Solution**: A production-ready Laravel + Vue starter kit that provides a complete admin dashboard foundation with authentication, RBAC, media management, and a modern SPA frontend using shadcn-vue components.

**Success Criteria**:
- All API endpoints protected by authentication and ability-based authorization
- Zero TypeScript errors on `npm run build`
- All tests passing via `php artisan test`
- PHP code formatted with Pint (`vendor/bin/pint --test` passes)
- API response time < 200ms for standard CRUD operations

## 2. User Experience & Functionality

### User Personas

| Persona | Description |
|---------|-------------|
| **Starter Kit Developer** | Developer who clones this repo to build a new admin/backoffice app. Needs clear patterns and extensible architecture. |
| **Admin User** | Has full access to all system features — manages users, assigns roles, configures the application. |
| **Regular User** | Limited access. Can edit own profile and perform actions granted by their assigned permissions. |

### User Stories

#### Authentication

| # | Story | Acceptance Criteria |
|---|-------|-------------------|
| US-1 | As a user, I want to log in with email or username + password, so that I can access the system. | Login accepts both email and username. Returns authenticated user JSON on success. Rate-limited to 5 attempts/minute per email+IP. |
| US-2 | As a new user, I want to register an account, so that I can start using the system. | Requires name, username, email, password (confirmed). Assigns `regular` role. Username and email must be unique. |
| US-3 | As a user, I want to reset my forgotten password via email, so that I can regain access. | Sends reset link to registered email. Token-based reset updates password. |
| US-4 | As a user, I want to verify my email address, so that the system confirms my identity. | Sends verification notification. Marks `email_verified_at` on success. |
| US-5 | As an authenticated user, I want to update my profile (name, email), so that my info stays current. | Validates unique email. If email changes, resets verification and sends new notification. |
| US-6 | As an authenticated user, I want to change my password, so that I can maintain security. | Requires correct current password. New password must meet strength rules. |
| US-7 | As an external client, I want to obtain an API token, so that I can authenticate from mobile or third-party apps. | POST `/api/sanctum/token` with email, password, device_name. Returns plaintext token. |

#### User Management

| # | Story | Acceptance Criteria |
|---|-------|-------------------|
| US-8 | As an admin, I want to list all users with search and filter, so that I can find specific accounts. | Paginated (10 per page). Searchable by name, username, email. Filterable by role and custom fields. Sortable by any column. |
| US-9 | As an admin, I want to create a user with assigned roles, so that I can onboard team members. | Requires name, username, email, password, roles. Avatar upload optional. Email marked as verified on creation. |
| US-10 | As an admin, I want to update a user's information and roles, so that I can manage accounts. | All fields editable except email. Roles can be synced. Password update optional. |
| US-11 | As an admin, I want to delete a user, so that I can remove inactive accounts. | Soft or hard delete. Returns confirmation. |
| US-12 | As a user, I want to upload/replace my avatar, so that I have a profile picture. | Accepts image files. Generates 3 conversions: small (300px), medium (600px), large (1200px). Replaces existing avatar. |

#### Roles & Permissions

| # | Story | Acceptance Criteria |
|---|-------|-------------------|
| US-13 | As an admin, I want full system access without explicit permissions, so that I can manage everything. | Admin role bypasses all permission checks via `Gate::before`. |
| US-14 | As a regular user, I want to edit my own profile, so that I can update my information. | Regular role has `edit-profile` permission. Does NOT have `view-users`, `create-users`, `update-users`, `delete-users`. |
| US-15 | As an admin, I want to search available roles, so that I can assign them to users. | GET `/api/roles/search` returns available roles. Throttled at 400 requests/minute. |

### Non-Goals

- Multi-tenancy or workspace isolation
- OAuth/social login (Socialite)
- Real-time features (WebSocket, broadcasting)
- Complex workflow/approval systems
- Email template customization UI
- Frontend CRUD pages (starter provides only the backend API + SPA shell)

## 3. Technical Specifications

### Architecture Overview

```text
┌─────────────────────────────────────────────────────┐
│                    Vue 3 SPA                         │
│  (Pinia stores, Vue Router, shadcn-vue components)  │
├─────────────────────────────────────────────────────┤
│              Sanctum (cookie-based)                  │
├─────────────────────────────────────────────────────┤
│                  Laravel 13 API                      │
│  Controllers → Services → Models → Database         │
├─────────────────────────────────────────────────────┤
│  Fortify (auth)  │  Spatie Permission  │  Media Lib │
└─────────────────────────────────────────────────────┘
```

**Request flow**: SPA → `GET /sanctum/csrf-cookie` → `POST /login` → Session cookie → All `/api/*` calls authenticated via session.

**Backend layers**:
- **Controllers** — Thin. Authorize, delegate to service, return response.
- **Services** — Business logic. `UserService`, `MediaService`, `RoleService`.
- **Form Requests** — Input validation.
- **Resources** — JSON output transformation.
- **Models** — Eloquent with traits (`Filterable`, `Searchable`, `HasRoles`, `InteractsWithMedia`).

### Integration Points

| Integration | Protocol | Purpose |
|-------------|----------|---------|
| Sanctum CSRF | `GET /sanctum/csrf-cookie` | Set XSRF-TOKEN for SPA |
| Fortify Auth | `POST /login`, `/register`, `/forgot-password`, `/reset-password` | Authentication lifecycle |
| User API | `GET/POST/PUT/DELETE /api/users` | User CRUD |
| Auth Check | `GET /api/users/auth` | Return current user with roles + permissions |
| Token API | `POST /api/sanctum/token` | Issue bearer tokens for mobile/external clients |
| Role API | `GET /api/roles/search` | List available roles |
| Avatar API | `PUT /api/users/{id}/avatar` | Upload/replace user avatar |

### Security & Privacy

- All API routes require `auth:sanctum` middleware (except token endpoint and Fortify public routes)
- CSRF protection via Sanctum stateful middleware
- Rate limiting: login (5/min per email+IP), API (60/min per user/IP), roles (400/min)
- Password hashing via bcrypt (Laravel default)
- Input validation on every endpoint via Form Requests
- Admin super-gate (`Gate::before`) grants all abilities to admin role
- Sensitive fields hidden from serialization (`password`, `remember_token`)
- CORS configured for SPA domains with `supports_credentials: true`
- Session stored in database with `same_site: lax`

## 4. Risks & Roadmap

### Phased Rollout

| Phase | Scope | Status |
|-------|-------|--------|
| **MVP (current)** | Auth, User CRUD, RBAC, Media, API, Test suite, SPA shell | ✅ Complete |
| **v1.1** | Frontend auth pages (login, register, reset), user management UI, dashboard page | Planned |
| **v1.2** | Profile settings page, avatar upload UI, toast notifications, data tables | Planned |
| **v2.0** | 2FA activation, activity logging, audit trail, notification system | Planned |

### Technical Risks

| Risk | Impact | Mitigation |
|------|--------|-----------|
| SQLite limitations at scale | Performance degrades with concurrent writes | Document MySQL/PostgreSQL swap procedure. SQLite is dev-only default. |
| radix-vue → reka-ui migration | shadcn-vue CLI may generate outdated imports | Pin reka-ui version. Monitor shadcn-vue releases. |
| TypeScript 5.9 → 6.0 gap | vue-tsc may not support TS 6 immediately | Stay on 5.9 until vue-tsc confirms compatibility. |
| Fortify views disabled | SPA must implement all auth UI client-side | Document all Fortify endpoints and expected payloads in API spec. |
| Session-based auth for SPA | Requires same-origin or configured stateful domains | Document CORS + Sanctum stateful domain setup for production. |

## 5. Constraints

- PHP 8.4+ required
- Node.js 20+ for frontend build
- SQLite as default database (replaceable with MySQL/PostgreSQL via `.env`)
- Vite 8 as frontend bundler (via laravel-vite-plugin)
- No external SaaS dependencies — runs fully self-contained
- Single `User` model (no multi-model auth)
