# Product Requirements Document (PRD)

## Background

This project is a starter kit for building modern admin dashboard applications using Laravel + Vue. It provides a solid, production-ready foundation so developers can focus on business features without setting up repetitive boilerplate.

## Product Objectives

1. Provide a secure, structured, and scalable Laravel backend API
2. Provide a modern Vue 3 SPA frontend with shadcn-vue UI components (architecture referenced from shadcn-vue-admin)
3. Complete authentication system (login, register, reset password, email verification, 2FA-ready)
4. User management with role-based access control (RBAC)
5. Media/file management integrated with Eloquent models
6. Architecture that is easy to extend for new features

## Target Users

- Developers building admin/backoffice applications
- Teams needing a starter kit with Laravel + Vue best practices
- Projects requiring multi-role user management

## Core Features

### Authentication & Authorization
- Login via email/username + password
- New user registration
- Password reset via email
- Email verification
- Two-factor authentication (2FA) — ready to enable
- Token-based auth for mobile/external clients (Sanctum tokens)
- Cookie-based session auth for SPA (Sanctum stateful)

### User Management
- CRUD users (create, read, update, delete)
- Avatar upload with automatic image conversions (thumbnails)
- Assign/sync roles to users
- Search and filter users
- Paginated listing

### Role & Permission
- Role-based system via Spatie Permission (Bouncer)
- Ability-based authorization (`view-users`, `create-users`, `update-users`, `delete-users`)
- Role assignment at user level

### Media Management
- File uploads associated with Eloquent models
- Automatic image conversions (small_thumb, medium_thumb, large_thumb)
- Replace existing media

### Frontend SPA
- Vue 3 with Composition API + TypeScript
- TailwindCSS for styling
- Pinia for state management
- Vue Router for client-side routing
- UI components based on shadcn-vue (radix-vue primitives)

## Non-functional Requirements

- **Performance**: API response < 200ms for standard operations
- **Security**: Input validation on all endpoints, CSRF protection, rate limiting
- **Scalability**: Service layer pattern allows business logic to grow without bloating controllers
- **Developer Experience**: Type-safe frontend (TypeScript), PSR-12 compliant backend (Pint)
- **Testing**: PHPUnit test coverage for all core features

## Constraints

- PHP 8.3+ required
- Node.js for frontend build
- SQLite as default database (replaceable with MySQL/PostgreSQL)
- Vite as frontend bundler

## Success Metrics

- All API endpoints protected by authentication and authorization
- Zero type errors on `npm run build`
- All tests passing (`php artisan test`)
- PHP code formatted with Pint (`vendor/bin/pint --test`)
